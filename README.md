# tg-monit

監聽 Telegram 頻道，一收到通知就用指定的 Chrome 設定檔開啟訊息裡的 tixcraft 連結。

## 第一次設定

1. 複製 `config.example.yaml` 為 `config.yaml`。到 https://my.telegram.org → 登入 → **API development tools** → 建一個 app，
   把自己的 `api_id`、`api_hash` 填進 `config.yaml`，並設定頻道與 Chrome 路徑。`config.yaml` 與 Telegram session 只保留在本機，不會提交至 Git。
2. 安裝套件：
   ```
   python -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   ```
3. 雙擊 `start.bat`，或手動執行（第一次會要求輸入手機號碼 `+886...` 與 Telegram 寄來的驗證碼）：
   ```
   set PYTHONUTF8=1
   .\.venv\Scripts\python.exe monitor.py
   ```
   登入後會產生 `tg-monit.session`，之後不用再登入。
   **這個檔等同你的 Telegram 登入憑證，不要外流。**

## 使用前提醒

- 先用 Default 設定檔把 Chrome 開著並登入拓元，開連結時只會多開一個分頁，不用重新啟動瀏覽器，速度最快。
- 頻道、Chrome 設定檔、去重秒數都在 `config.yaml` 調整。

## 開分頁的速度：擴充功能橋接

擴充功能的背景程式會連到 `monitor.py` 開在 `ws://127.0.0.1:8765` 的本機橋接，收到網址直接開分頁，
比每次執行 `chrome.exe` 快 100–300ms。橋接只接受 Chrome 擴充功能連線、只開拓元網址。

- 監控視窗出現「🔌 擴充功能已連線」就代表走快速路線；擴充功能沒連上時會自動改用 `chrome.exe` 開，不會漏開。
- `monitor.py` 和 Chrome 誰先開都可以，擴充功能每幾秒會自動重連。
- 每筆紀錄的 `本機Xms(擴充/Popen)` 是收到訊息到送出開分頁的耗時；
  `TG≤Nms` 是 Telegram 端延遲的**上限** —— 訊息時間只到整秒，實際延遲在 N-1000 到 N 之間。
- 需要 Chrome 116 以上。

### 找出慢在哪裡（1.6.0 起）

原紀錄的 `本機Xms(擴充)` 只量到把開頁指令送給擴充功能，不包含 Chrome 建立分頁、網站回應、驗證碼圖片載入及送出。`TG≤Nms` 也不含 Genie 偵測庫存到發布訊息之前的等待。

1.6.0 會額外印出 `[流程]` 紀錄：頁面開始、票數已選、開始辨識、驗證碼已填、已按確認張數，以及辨識失敗／分歧或售完關閉。每筆列出頁面起算耗時，透過擴充功能開啟的分頁也會列出收到通知後及開頁指令後的耗時。不經橋接開啟或重新啟動背景程式後的既有分頁，可能只有頁面起算時間。紀錄只傳回本機，不含驗證碼文字及圖片。

- 若直接售完關閉，且尚未出現票數已選，表示這次購票頁未進入可選票狀態，不能藉此判定一定是 OCR 太慢。
- 若停在「辨識失敗／分歧」，助手沒有自動送出，需要手動輸入或換圖。
- 「已按確認張數」代表已嘗試點擊，不代表官網已確認購票成功。

同步縮短欄位變動後的固定 50ms 排程等待。OCR 保持原本接受規則，先檢查兩模型對處理圖的結果；分歧時只跑兩次，一致且有一個原圖結果支持時跑三次即可，必要時才跑第四次。這些改動不保證搶票成功。

套用本次更新需重新啟動 `start.bat`、重新載入版本 **1.6.0** 的擴充功能，再重新整理現有頁面。

## 開啟網站後：選票數與驗證碼

### 售完分頁自動關閉（1.5.0 起）

拓元購票頁或場次頁出現「此場次/區域已售完」（也支援「此場次已售完」「此區域已售完」）的瀏覽器提示時，助手會直接關閉該分頁，不需再按提示的確定。這項功能獨立運作，不需啟動 Python 監控。只判斷指定的售完提示，不會因頁面中某一列標示售完就關掉整頁；驗證碼錯誤、登入提醒及其他提示仍照常顯示。

更新後請在 `chrome://extensions` 重新載入助手，確認版本 **1.5.0**，再重新整理現有分頁。已經跳出的舊提示需先按一次確定，新載入的頁面才會套用提示攔截。

第一次需在上述同一個 Chrome 設定檔安裝本機擴充功能：

1. 開啟 `chrome://extensions`，啟用右上角「開發人員模式」。
2. 點「載入未封裝項目」，選擇此專案內的 `chrome-extension` 資料夾。
3. 點工具列的擴充功能圖示 →「TG 拓元購票助手」，設定票數並儲存，預設為 **1 張**。
4. 已經開著的購票頁需重新整理一次，之後 Telegram 開的新分頁會自動套用。

進入 `/ticket/ticket/` 購票頁後，助手會選擇設定的張數，觸發網站欄位更新，自動勾選購票同意欄位，並將游標移到驗證碼輸入框。預設會自動辨識圖片、填入四個英文字母，再自動按「確認張數」。後續付款步驟請自行操作。手動取消勾選後，不會持續勾回。

### 自動確認張數（1.3.0 起）

「辨識填入後自動按確認張數」預設啟用，可在擴充功能設定中關閉。只有這次 OCR 成功填入、票數仍符合設定、購票同意欄位已勾選、表單驗證通過，且找到同一表單中的「確認張數」或「確認票數」按鈕時，才會自動點擊。只檢查辨識結果格式，無法在送出前保證答案正確。

每個頁面最多自動點擊一次。網站顯示驗證碼錯誤或其他購票失敗訊息後，請手動處理，不會無限重送。若辨識期間你手動輸入，或票數、同意欄位有變動，會保留內容並交由你手動確認。此功能只處理票數頁，不會操作後續付款按鈕。

### 本機驗證碼辨識（1.2.0 起）

請保持 `start.bat` 開啟，等監控視窗顯示「驗證碼雙模型辨識已就緒」。擴充功能會將頁面上已顯示的圖片經既有 WebSocket 橋接傳給本機 Python，使用 [ddddocr](https://github.com/sml2h3/ddddocr) 辨識，圖片不會送到外部辨識服務，也不會另外向網站要求一張新驗證碼。

首次安裝辨識套件可在專案目錄執行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

`start.bat` 會優先使用專案的 `.venv`。更新後關閉原監控視窗並重新啟動 `start.bat`，在 `chrome://extensions` 重新載入助手（版本 **1.6.0**），並重新整理購票頁。擴充功能設定裡可分別關閉「本機辨識並填入驗證碼」與「辨識填入後自動按確認張數」。頁面提示與擴充功能設定會顯示版本；辨識完成但自動送出關閉時也會明確提示。擴充功能若連到舊版辨識程式，會要求先重啟監控，避免繼續套用舊版結果。

### 雙模型檢查（1.4.0 起）

針對藍底白字驗證碼，先擷取白色文字、轉成白底黑字並加邊框；其他背景保持原樣。預設與 Beta 模型各讀取原圖與處理圖，四次辨識至少三次相同，且兩模型對處理圖的結果也必須相同，才會填入。結果分歧時會停止填入與送出，提示手動輸入或換圖。

這是辨識一致性篩選，不能當成正確率或信心分數；兩模型仍可能一起辨識錯誤。新增處理只經合成圖驗證，尚未取得實際拓元驗證碼的標註資料，因此不宣稱實際準確率提升幅度。較難的圖片會更常要求手動處理。

辨識可能出錯；若要自行核對後送出，請關閉自動確認張數。辨識失敗時可直接手動輸入，或點網站圖片換圖後重新辨識。換圖會清除助手填入的舊結果；辨識期間你手動輸入的內容會保留。未啟動本機監控或橋接斷線時，仍可手動完成購票。

如果連結是 `/ticket/area/` 選區頁，請先手動選擇票區。登入、選場次、排隊及其他驗證也需依網站提示完成。票數不足時會提示，不會擅自減少張數。多個票種同時出現時，會排除票種列中標示身障、敬老、學生等優惠或資格限定的票；若剩下唯一一般票種（例如「單場票」），就自動選擇該票種。如果仍有多個一般票種，或只剩優惠票，則提示手動選擇。你手動調整已選票數後，助手不會持續改回預設值。

票數與啟用狀態保存在 Chrome 擴充功能內，儲存後會立即套用至已開啟的頁面。更新擴充功能程式後，請在 `chrome://extensions` 按重新載入，再重新整理購票頁。

擴充功能採用 Chrome 的 [content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts) 在拓元票務頁操作欄位，不需要另開瀏覽器設定檔。若網站修改欄位名稱，需更新 `chrome-extension/content.js` 的選擇器。
